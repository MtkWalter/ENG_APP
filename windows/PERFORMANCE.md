# 長對話效能分析（2.0.4）

分析範圍是 Milo 在聊天網頁中執行的畫面輔助腳本。原先每次文字更新都可能掃描整段歷史、反覆寫入相同排版屬性，捲動時還會重新查找訊息和量測頁面。

## 改動

- 文字加寬只處理新加入的訊息與容器，已設定的屬性不重複寫入；移除失去連線的 DOM 參照。
- 輸入區與語音動畫的檢查略過訊息內的逐字更新；輸入區的小字搜尋限於底部區域。短時間的介面更新合併處理，動畫的 transform 變動不再引發整頁檢查。
- 快取訊息、捲動容器與底部操作列；用尺寸變化通知追蹤內容高度。訊息換行時只更新捲動，視窗或底部區域改變時才重算避讓空間。
- 手動向上捲動或選取文字時暫停跟隨，回到最底部才恢復。加入滑鼠拖動與鍵盤捲動處理。

## 可重現測試

`npm run test:performance` 以 600 則模擬歷史訊息、120 次逐字更新，對照 2.0.2 的原始腳本與目前版本。更新交替使用文字節點原地更新與節點替換，涵蓋兩種常見串流呈現方式。原始 Android 腳本仍保留在 assets/android；舊版文字加寬腳本僅作測試基準，放在 test/fixtures。

本機 Linux / Electron 45 的一次結果：

| 更新期間的指標 | 2.0.2 | 2.0.3 |
| --- | ---: | ---: |
| document 全域查詢次數 | 360 | 0 |
| 其中整段訊息／全頁文字查詢 | 240 | 0 |
| 重複寫入 Milo 排版屬性 | 36,060 | 0 |
| 畫面更新回呼合計耗時 | 480.1 ms | 22.2 ms |
| 最長單次回呼 | 14.5 ms | 3.1 ms |

這是合成頁面上的輔助腳本測量，時間會隨機器與負載變化；它不代表整個 ChatGPT 頁面或模型回覆加速相同比例。測試以查詢及屬性寫入數作回歸判斷，不以固定耗時門檻判定不同電腦的結果。

同一測試另確認：手動捲動不被拉回、回到底部恢復跟隨、選字時畫面穩定、底部操作列變高時保留文字空間，以及新訊息的加寬與跟隨。Windows 建置也執行這組測試，結果保存在 test-results/performance.json，隨測試證據 artifact 提供。

## 2.0.4 的追加分析

平滑捲動：在測試頁啟用 `scroll-behavior: smooth`，加入新文字後檢查四個動畫影格內是否跟到底部。2.0.3 的直接 `scrollTop` 指派會觸發平滑動畫，回歸測試失敗；改為明確的即時自動跟隨後通過。網站自己的樣式保留，使用者手動捲動及選字仍會暫停跟隨。

分階段訊息：網站可能先掛載空白回合，再加入內容。原先把空白回合視為完整訊息，會漏掉稍後加入的文字容器；現在只略過既有作者內容內部的更新。新增的分階段加寬、跟隨，以及程式碼／清單更新不做全域掃描三項檢查均納入測試。

翻譯：實際模型測試發現，快速取消再建立 Worker 會重載原生推論元件，可能出現 `Module did not self-register`，並誤判模型需要重新下載。改用同一個 Worker、共享取消旗標與最多一筆最新待處理工作。取消在生成步驟之間生效，正在執行的原生步驟仍需完成。關閉程式才終止 Worker；模型快取不因一般取消而失效。實際模型整合測試涵蓋連續切換及取消後再次翻譯。

朗讀：已完成且通過 WAV 驗證的音訊可在記憶體中重用，最多 8 筆、8 MiB；超過單筆上限的音訊仍可播放，但不加入快取。失敗與已取消的合成不快取。`npm run test:speech` 在 Windows 呼叫真實語音引擎，確認同一段重播只啟動一次 PowerShell，並輸出 `speech-performance.json`；耗時不作跨機器固定門檻。

上述改動減少 Milo 自身的重複工作，不能保證網站、網路或所有電腦完全沒有停頓。

## 2.2.1 上傳相容性

修正附件工具列不在最近表單內、新版中英文標籤，以及網頁縮放後的點擊座標。上傳按鈕與傳送按鈕改用和頁面量測一致的 CSS 座標。附件尋找僅在載圖操作時執行；短暫的選單等待和拖放確認有時間上限，不新增常駐掃描。長對話效能測試繼續保留。

## 2.2.2 語音畫面與教材接收

重新分析語音時發現，字幕可能出現在一般訊息節點外。先前「語音專注」會把這些文字替換誤認為對話結構變動，重新查找歷史，也可能隱藏說話／暫停／繼續按鈕與字幕。現在只在加入或移除實際回合、作者內容或底部操作區時更新結構，保留語音控制、字幕及含音訊／影片的容器。這不會操作網站的音軌、錄音或 WebRTC 物件。

實際 Electron 合成頁面、600 則歷史、120 次訊息外字幕替換的一次比較：原實作 119 次歷史查找、259 次全域查詢，修正後兩者皆為 0。修正後輔助回呼合計約 9.5 ms／2.16 秒；時間僅供該次測量參考。既有 11 項捲動／選字／底部避讓檢查，以及新增 5 項語音控制、字幕、媒體容器與播放連續性檢查均通過。證據仍在 `test-results/performance.json`。

背景音訊保護使用 Electron 原生播放與 audible 狀態通知，兼容沒有 `media-started-playing` 的 WebRTC 路徑；共用一筆防止程式休眠的請求，不新增頁面輪詢。停止播放、換頁、渲染程序退出或關閉時清理，與視窗顯示時的螢幕限制分開管理。`test:media` 真正把接收串流接到 HTMLAudioElement，跨字幕更新、查字、縮放、焦點切換、最小化／還原持續播放至少 15 秒，檢查封包、播放時鐘、非零音訊能量與請求釋放。

目前「完整網站介面」的合成測試未重現語音中斷；上述結果不能證明使用者實際 ChatGPT 連線、插話偵測或喇叭回音問題已修復。瀏覽器語音按鈕會開啟目前對話，供已確認瀏覽器正常時接續使用。


## 2.4.0 移除右側遊戲

移除遊戲題庫、角色素材、拼圖、餵食、闖關、教材編輯器、遊戲 IPC，以及僅供遊戲使用的圖片文字辨識與建題元件。啟動不再建立遊戲狀態，也不提供背景辨識或自動建題工作。Tesseract 與英文辨識資料不再隨安裝檔提供。

保留 ChatGPT、字典、Windows 朗讀、選用整句翻譯，以及三種需要使用者明確操作的圖片教學；圖片正規化仍使用既有非同步影像處理。長對話、字幕、捲動及持續播放測試維持執行。

`test:no-games` 確認畫面與對外 API 都沒有遊戲功能，舊遊戲 IPC 請求會被拒絕；`test:images` 與 15 種上傳相容情境確認圖片教學仍可使用。打包後 EXE 再次檢查字典、朗讀、翻譯與三種圖片模式。
